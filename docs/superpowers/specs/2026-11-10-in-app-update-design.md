# 应用内更新设计

用户已确认：使用公开仓库 stengger/NetGuardian 的正式 Releases，在设置页检查、下载、校验并安装更新，最后发布 v1.1.0。

## 范围

- 沿用 .NET 8、WPF、WPF-UI 和 Inno Setup，不新增 NuGet 依赖。
- 检查更新由用户触发；不增加启动自动检查和强制更新。
- 新增更新模块、设置页控件、安装协调脚本及测试；原网络检测、恢复策略和 IPC 不改。
- 配置与日志保留在原位置；更新凭据不需要配置，不改变原配置格式。
- 统一程序集与安装包版本为 1.1.0，标签指向通过验证的源码提交。

## 更新流程

设置页显示当前版本、更新状态、新版本说明和检查按钮。发现新版本后提供下载，展示进度及取消；下载成功且 SHA256 相符才出现安装按钮。网络失败、GitHub 限流、缺少附件、取消和校验错误均显示可恢复的行内状态。

服务只接受公开仓库的 HTTPS 正式 Release 及其固定命名的 win-x64 安装包和校验文件。忽略草稿、预发布和不高于当前版本的版本；遵循 Windows 系统代理，不硬编码本机代理端口。下载至受保护的机器级缓存，临时文件校验后才转为完整安装包。

用户确认安装后，启动独立 PowerShell 协调进程。它重新校验安装包、安装目录及进程身份，备份程序文件、卸载注册信息和所属后台任务，发出准备完成信号。界面沿用原有退出收尾流程关闭；协调进程等待准确的原界面退出，停止属于当前安装目录的监督任务并请求守护安全停止。超时不强杀。

随后调用现有 Inno Setup 安装包进行原目录升级。安装成功后检查程序集版本，恢复原任务定义、启用与运行状态，重新启动界面。安装失败时停止继续升级，恢复已备份的程序、卸载信息和任务；只有恢复核验成功才启动原界面。备份、安装日志和结果留在受保护的更新目录。恢复失败给出明确错误及日志位置。

仅正式安装目录支持安装协调；开发运行仍可检查与下载，安装按钮解释当前运行目录不支持原地更新。所有增删文件操作先核实绝对路径和重解析点，操作目标限于当前安装与更新目录。

## 模块

- `NetGuardian.Core/Updates`：版本与 Release 解析、HTTP 检查、流式下载及校验，接口可通过内存 HTTP 测试。
- `NetGuardian.App/Updates`：会话状态、受保护缓存、外部安装启动和准备握手。
- `MainWindow.Updates.cs` 与设置 XAML：WPF-UI 展示和命令，沿用设计令牌、原生焦点和统一确认框。
- `scripts/update-netguardian.ps1`：独立安装事务、备份、任务归属检查、恢复及日志。
- 共享版本属性与发布脚本：以同一个版本生成程序集和安装包；打包安装协调脚本。

## 验证与交付

核心测试覆盖版本、附件来源、HTTP 错误、取消、不完整下载及校验失败。桌面测试覆盖状态按钮、焦点、窄窗口和长发布说明。脚本测试用隔离目录和系统调用替身验证成功、停止超时、安装失败与回滚失败，避免更改开发机网络及任务。

每个逻辑步骤运行构建、相关测试及全量回归后中文提交。最终构建安装包、更新本机两处界面目录、核对文件与进程、推送主分支并发布 v1.1.0。真实安装维护需要用户确认的 Windows 权限提示，现有界面部署前由用户从托盘退出。
