# Wi-Fi 网页认证与自动恢复设计

## 目标与范围

远程连接因校园网认证失效而中断时，NetGuardian 的后台守护应能自行尝试恢复。先通过原 Wi-Fi 完成认证并验证公网，失败就按恢复优先级尝试备用 Wi-Fi。Windows 用户尚未登录时，已启用的开机守护也应能完成这条流程。恢复结果以本机公网探测为准，远程会话的重连由远程软件处理。

首版覆盖可重复执行的网页登录流程，包括账号密码、固定下拉选项和单按钮放行。每个无线配置单独启用自动认证。短信验证码、扫码、需人工批准的登录、专用客户端和无法验证身份的登录站点，在无人值守时按认证失败处理。不同站点的兼容性由用例和现场验收确认。

## 判断是否需要认证

判定针对当前 Wi-Fi 的连接状态。同一个 Wi-Fi 在认证有效期内可能已可访问公网，过期后才再次出现门户。SSID 用于关联配置，每次恢复都重新核对当前 Windows 无线配置和网卡。

| 探测结果 | 判定与动作 |
| --- | --- |
| 当前 Wi-Fi 的公网 HTTPS 探测通过 | 当前网络可用，结束恢复。 |
| 网络公布的 CAPPORT 状态接口可通过证书校验访问，并报告 `captive: true` | 当前接入受限。若接口给出了门户地址，将其作为本次发现的候选入口，自动填表前仍须验证站点和表单。 |
| 固定响应的 HTTP 联网探针返回重定向，或者返回替换探针响应的门户 HTML，且最终认证站点和表单匹配已验证配置 | 判定当前需要这项认证，进入自动登录。使用本次发现的入口和会话参数。 |
| HTTP 探针跳到未知站点、返回陌生 HTML、遇到证书问题，或表单不再匹配 | 记录为疑似认证或入口不可用，停止自动填表，公网仍不通时尝试备用网。 |
| 仅见超时、DNS 失败或空响应 | 公网不可用，原因未确定，沿用故障恢复策略。 |

完整诊断在公网失败且当前 Wi-Fi 已关联、具有可用接口地址时检查门户。Windows 的联网状态可以作为提醒信号，成功判定继续采用 NetGuardian 自己通过当前 Wi-Fi 发起的公网探测。CAPPORT 的 DHCP/路由通告发现和状态接口分别见 RFC 8910 与 RFC 8908。首版优先打通 HTTP 发现和认证闭环。CAPPORT 作为同一发现模块的后续输入，首版不依赖它。

## 首次配置与凭据边界

1. 用户在 Wi-Fi 恢复列表中选中当前网络，进入「设置自动认证」。向导通过当前 Wi-Fi 发现登录入口，展示最终站点的域名、协议和登录页面。若当前认证仍有效，等下次自然弹页时再完成配置。
2. 向导识别账号框、密码框、固定下拉选项和提交按钮。识别不准确时，由用户点选。保存控件的角色、标签或结构定位以及固定选项。跨站点表单或脚本请求需要显式配置并验证提交站点，后台执行时按白名单检查。
3. 用户在本机录入凭据并发起一次试登。认证页面、跳转和提交使用当次会话。只有试登后同一 Wi-Fi 的公网探测通过，才把该配置标记为「已就绪」。当用户只需勾选同意或点击放行时，保存的是用户已确认的步骤，不需要账户凭据。
4. 正常配置保存已确认的 HTTPS 来源、允许的登录路径和控件定位。来源按协议、主机和端口精确匹配。证书无效、明文提交、子帧或提交目的地与配置不符时，停止该次操作。临时 URL 查询参数、Cookie 和表单令牌只在当次会话中使用。
5. 为现有 `SYSTEM` 守护提供可在用户未登录时读取的加密凭据。系统守护通过受访问控制的本机接口接收凭据并加密保存。常规配置仅保留引用，落盘文件限制管理员及 `SYSTEM` 访问。日志记录脱敏的站点与结果，过滤账户、密码、完整查询串、会话数据和表单内容。

后台运行网页登录时使用独立低权限进程和一次性浏览器配置，隔离日常浏览器的 Cookie、扩展与配置。填入凭据前检查当前页面、控件所属文档及允许的网络目的地。执行环境须能证明登录页访问和表单提交走目标 Wi-Fi，且凭据提交期间的外发请求受约束。无法验证这些条件时，当轮直接走切网。后台浏览器运行方式及接口绑定通过 Windows 无交互会话原型验收后确定。

## 认证和切网顺序

- 当前 Wi-Fi 仍关联时，先使用完整诊断所得的认证证据。确认需要认证且已就绪，就原地自动登录，避免重连打断本次会话。账号明确被拒绝、套餐到期、登录需要人工操作、认证超时或登录后公网仍不通时，进入备用网流程。仅有一般故障证据时，沿用现有重连等恢复步骤。
- Wi-Fi 已断开时，按原策略连接候选。关联后先验证公网，失败再检查认证。每个候选完成同一套验证。页面提示「成功」只用于决定何时立即复测，最终以当前 Wi-Fi 公网探测通过为准。测试期间如连接发生变化，作废旧结果。
- 同一配置在一轮恢复中最多提交一次。认证和复测使用可取消的子时限，纳入整轮恢复截止时间。优先为一个可尝试的备用候选预留连接和公网验证时间。剩余预算不足时提前结束认证步骤。候选沿用启用状态、可见网络优先级和退避，确认门户故障时不据此升级为设备重启。
- 明确的密码错误或套餐到期写入该配置的暂停状态。用户更新凭据或续费后可点「重新验证」。一般超时、站点异常或原因未知按短期退避处理。后续检测允许识别该网络已自然恢复可用。若所有候选均失败，保留本轮各候选原因，退避后再检查。
- 自动切网沿用项目现有开关。开启且有可尝试的备用配置时，认证失败自动切换。关闭时记录失败原因。切到健康的备用网后维持连接，下一次实际发生故障再评估其他候选。

## 与现有代码的接入点

- `NetGuardian.Core` 的完整探测报告携带独立的门户判定和证据。`MonitoringEngine` 在当前 Wi-Fi 重连之前判断是否可原地认证，在 `ConnectAndValidateAsync` 的候选验证阶段复用同一套流程。继续由 `RecoveryPlanner` 提供候选顺序，由既有公网探测验证恢复结果。
- `NetGuardian.Guardian` 负责后台执行、读取受保护的凭据和统一管理当轮尝试。界面与守护交接时，认证任务同一时刻只由一个执行方持有。`NetGuardian.App` 提供首次配置、测试登录、重新验证和认证事件展示。

## 验收

| 场景 | 通过条件 |
| --- | --- |
| Wi-Fi 上电后已经可访问公网 | 不弹认证提示、不提交凭据、不触发切网。 |
| HTTP 重定向或 HTML 门户出现，会话地址在重连后变化 | 首次配置发现并验证入口。再次认证使用新的会话地址。已配置的页面可完成提交和公网复测。 |
| 账号密码、固定选项、单按钮放行 | 各有可重复测试的门户样例。页面出现多个匹配控件时停止填表，由用户调整配置。 |
| 假门户、未知域名、证书错误、改版后跨站提交 | 自动化不填写或提交凭据，日志保留脱敏失败原因，备用网可用时完成切换。 |
| DNS 或探针超时、同时接入有线网 | 超时不被误报为已确认的认证页。有线网可用不能替代目标 Wi-Fi 的公网验证。 |
| 登录被拒、套餐过期、验证码或页面声称成功但公网不通 | 认证预算耗尽前结束当前尝试，按策略切到备用并验证公网。明确的密码错误或套餐到期暂停该配置的自动提交。 |
| Windows 开机后用户未登录，管理界面关闭或远程会话中断 | 使用真实计划任务及守护身份验收。认证过期后，后台完成自动登录或在恢复时限内切到可用备用网，事件可追溯。 |

东莞理工学院的页面作为首个现场样例。截图可确认有账号框、密码框、登录按钮及带查询参数的入口。认证重定向、凭据实际提交目的地、页面兼容性和远程恢复时长均以现场验收记录为准。现场验收安排在可本机操作、可接受短时断网的窗口。
