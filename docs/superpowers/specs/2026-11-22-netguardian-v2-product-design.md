# NetGuardian v2.0 功能设计

**评审稿 · 2026-11-22 · 以 v1.2.0 为基础**

面向偶尔需要远程维护的 Windows 实验室电脑。管理员打开软件，首先需要知道这台电脑现在能访问什么、上一次断网如何恢复。维护软件时，即使电脑没有代理、GitHub 无法访问，也应能通过项目维护的备用源取得正式更新。

## 1. 版本范围

| 交付批次 | 用户得到的能力 | 完成标志 |
| --- | --- | --- |
| 可提前交付到 1.2.x | 网关、DNS 等读数区分最近实测、本轮跳过和本次失败 | 同一网络上的完整检测之后接轻量检测，读数带测量时间。切网后，旧网络的读数退出首页 |
| 2.0 首发 | 三个日常入口、故障时间线、按网络区分的指标、免代理更新、旧版首次升级入口 | 能从首页追踪一次断网到公网复测，能在 GitHub 全链路不可达的目标网络完成一次正式升级 |
| 2.1 候选 | 工作服务监测、恢复策略预演 | 两项各自完成现场验证后交付。基础数据在 2.0 开始记录 |

**已确认的现场条件**是代理时有时无。首发更新流程以零配置为默认。三个入口和 2.1 的范围是本稿的产品取舍。

## 2. 三个一级入口，设置固定在侧栏底部

| 入口 | 打开后能做什么 | v1.x 功能去向 |
| --- | --- | --- |
| **概览** | 看当前网络、守护是否运行、最近验证时间。首要操作为「立即检测」。有故障时，点击当前故障就能看进展 | 首页保留。网关、DNS 和 HTTPS 三项指标点开后查看各自的采样记录 |
| **故障记录** | 默认按一次中断列出时间、可观测的持续时长、最终结果。选中一条，在同一页展开步骤、证据和原始日志 | 首页最近事件、自动恢复历史和事件日志链接到同一条记录。保留「全部日志」筛选和导出 |
| **网络与守护** | 管理当前连接、备用 Wi-Fi 的顺序及恢复条件。网络、策略、诊断用页内入口切换 | Wi-Fi 扫描、网卡与 DNS 配置按所选网卡排列。测速、网站检测、公网 IP 和诊断报告收入「诊断工具」 |

概览第一行显示连接名称、联网结论及其验证时间。第二行并排放三个等宽指标。下方留给当前故障或最近一次故障。健康时使用紧凑的一行摘要，发生故障才展开进度。数字下方保留采样说明，避免为每一条提示增加卡片。沿用现有深浅色主题、系统字体、键盘焦点和高对比度资源。窄窗口让指标自然换行，主操作和故障结果仍可见。扫描成功在 Wi-Fi 页反馈，扫描失败进入日志。

## 3. 首页指标按实际测量更新

v1.2.0 的轻量检测采集接口状态、IPv4 和公网 HTTPS 结果。首页收到新报告后整组重绘，会把该轮跳过的网关 Ping、DNS 查询均值显示为「—」。v2.0 为每项指标分别保存最近一次尝试、最近一次有效测量、测量时间和所属网络。原始诊断报告保留本轮实际执行的探针。

| 当前情况 | 首页示例 | 点击后看到什么 |
| --- | --- | --- |
| 从未测量 | 等待首次测量 | 检测项目与「立即检测」 |
| 完整检测成功 | 12 ms · 刚刚测得 | 本轮成功数、有效样本数与采样时间 |
| 同一网络的轻量检测跳过 DNS | 12 ms · 3 分钟前测得 | 上次 DNS 完整检测及本轮跳过的原因 |
| 最新一次实际测量全部超时 | 本次超时 · 14:08 | 此次失败明细，下方另列最后一次成功值 |
| 样本超过新鲜期 | 上次 12 ms · 已过期 | 绝对时间及手动复测入口，历史样本用次要色显示 |
| 切换网络或关键配置变化 | 等待新网络测量 | 新网络的上下文，原网络读数归入历史 |

首发建议以三个正常检测间隔为新鲜期，限制在 5 到 30 分钟之间，休眠期间按实际经过时间计龄。用接口标识、连接代次和已知的 Wi-Fi、网关、DNS 配置识别测量上下文。轻量报告缺字段时，结合接口变化通知判断。归属无法确认时显示待测。只有部分 DNS 目标成功时，均值旁标出成功数，详情保留失败项。点击历史读数打开它所属的那次检测。

## 4. 故障记录围绕一次中断

一次公网故障从首次确认失败的完整诊断开始，到再次通过公网验证结束。轻量探测失败先触发完整诊断。自动恢复仍按已保存的连续失败门槛和冷却执行，同一次中断可以包含多轮恢复。网关未响应而公网探测通过时，首页可以同时显示「公网可用」和「网关 Ping 超时」。

以下为一条虚构的界面样例。时间精度来自实际检测记录。

| 时间 | 用户看到的步骤 |
| --- | --- |
| 14:05:00 | 首次检测到公网不可达，当前连接为「实验室主网」 |
| 14:05:12 | 达到恢复阈值，尝试重连主网 |
| 14:05:24 | 主网复测失败，尝试连接「实验室备用网」 |
| 14:05:31 | 已连接备用 Wi-Fi，正在验证公网 |
| 14:05:36 | 备用网公网验证通过。本次观测中断 36 秒 |

每条故障有稳定标识。每轮动作记录触发原因、执行者、目标、结果和验证证据。公网自行恢复可单独结案。尝试切换、已连上 Wi-Fi、已恢复公网分别计数。所有入口使用同一记录，界面重开、前后台交接按事件标识去重。服务停止或电脑休眠造成的空档标为「期间缺少观测」，仅统计有依据的起止和动作。旧日志按已有的断网、恢复边界只读展示，无法归属的动作在原始日志中保留。

## 5. 免代理的软件更新

### 从用户点击到完成

1. 「设置 → 软件更新」默认选择「自动」。GitHub 正常时沿用系统网络配置。版本接口超时、连接中断、限流或服务暂时不可用时，自动查询项目维护的备用源。首发以单源检查 5 秒、两源合计 12 秒为交互目标，下载使用独立超时。
2. 备用源独立提供稳定版清单、中文说明、安装包和签名元数据。它的解析、寻址、文件下载和校验均可在 GitHub 全部相关域名不可达时完成。代理可用时照常检查。代理关闭或遗留本机无响应的代理端口时，自动模式可通过获准的直连线路访问项目备用域名。成功切换后，本次更新优先复用这条线路，用户仍可取消。仅允许代理的企业环境遵从管理员路由设置。
3. 界面显示「已从备用源找到 v2.0.x」或「主源下载中断，已从备用源继续」。下载继续使用受保护的缓存、大包最多四路并行和断点恢复。跨源复用分段前须核对同一签名清单中的版本、长度和 SHA-256。服务器忽略范围请求时回到该源的单连接下载。
4. 两源均无法使用时，行内分别显示失败阶段、错误原因、已保存的下载量及「重试」。仅能读到过期清单时显示上次成功检查的时间。更新失败只反馈在设置页，与本机网络恢复的触发条件独立。
5. 命中有效缓存或下载完成后，校验整包，通过后呈现「安装并重启」。继续沿用现有的用户确认、安装目录核验、备份、守护任务交接和安装失败回滚。设置中可看到实际使用的源及最后一次更新结果。

### 发布、信任和首次升级

- 备用源建议采用项目控制域名下的静态 HTTPS 站点。实验室电脑可以匿名只读获取文件。维护者可迁移对象存储或更换托管服务，客户端继续使用同一域名。首版只分发本项目的正式更新。
- 项目发布方对稳定版清单签名。客户端内置受信公钥，校验渠道、签名、发行序号、有效期、版本、架构、文件名、长度及整包摘要。两个来源提供相同内容。签名无效、回退到已见过的旧发行序号或包摘要不一致时，显示安全错误并阻止安装。发布方负责签名密钥备份、轮换与紧急撤销演练，服务端仅托管公开产物。
- 发布先上传两个源的不可变版本文件，再从两个源回读大小与摘要，最后切换各自的稳定版清单。双源都通过公开验收后才对外宣布完成。短时版本不齐时，缓存绑定到所选已签名版本；缺少该版本的源只提示暂未同步。国内地址由维护者选定，启用条件是从目标实验室的无代理网络实测可达、可长期维护并可承受安装包流量。
- v1.1.6、v1.2.0 等现有客户端只认识 GitHub。提供固定的项目分发入口和同一正式离线安装包。旧版在 GitHub 或代理可用时可走原有通道。完全不可达时由维护方通过可信渠道分发或用移动存储介质带入，并从独立可信渠道核对首包摘要。完成首次安装后，后续版本自动使用双源。首次升级保留原有 Wi-Fi 优先级、守护策略和日志。

## 6. 后续功能怎样使用首发数据

**工作服务监测。** 在「网络与守护」添加管理员指定的 HTTPS 健康检查地址，如实验仪器预约系统。同屏分别显示公网和该服务从本机访问的结果。仅业务服务失败时，默认提醒并给出检测详情，公网恢复策略仍由公网证据触发。外部电脑能否连回实验室属于另一观测方向。

**策略预演。** 在保存策略前选取一条历史故障，按拟定的失败阈值、候选顺序、冷却和风险开关重放决策。每步显示当时的实测证据、预演会选择的动作和缺少的输入。预演只读，假设动作的实际结果显示为「无法从历史验证」。复用现有恢复决策逻辑，避免预演解释和实际行为分歧。

## 7. 落地与验收

先并行定义检测上下文、故障事件和签名发布清单。先用本地双源搭起升级测试，再在目标实验室实际验收线路。前台与后台写入兼容的结构化事件，最后接入概览和故障详情。读取旧配置和日志时保留原件，迁移和恢复结果需要能在一次真实升级后核对。

| 编号 | 场景 | 首发通过条件 |
| --- | --- | --- |
| A1 | 完整检测后连续轻量检测，随后发生 DNS 超时、切网、休眠恢复 | 前两项延迟在同网跳过时带时间保留，真实失败和新网络有独立显示，超龄数据可识别 |
| A2 | 同一次故障内发生三次切换尝试，只在最后一次恢复公网 | 首页及历史只有一条故障，详情含三次切换尝试和一次已验证的公网恢复，持续时间可复算 |
| A3 | 自动恢复关闭、前后台交接、重开界面、读取 v1.x 历史 | 自然恢复有独立结论，交接无重复计数，缺失证据显示为未知，原日志可读 |
| A4 | 在目标实验室关闭代理，令 GitHub 接口、下载及跳转域名都不可达 | 通过备用源独立完成发现、下载、验签、安装、重启，版本、设置和守护任务状态正确 |
| A5 | 系统代理时有时无，主源下载中断 | 自动换源，支持范围请求时沿用同一包的有效断点。界面显示线路、进度和失败阶段 |
| A6 | 签名错误、过期清单、降级清单、同名不同包、两源均离线 | 拒绝不可信或过期的新安装，旧发行序号无法覆盖新记录。双源失败可重试，正式安装保持可用 |
| A7 | 从 GitHub 不可达的 v1.1.6 首次离线升级 | 通过可信入口安装，原有策略与日志可读。再用新客户端从备用源发现下一个测试版本 |
| A8 | 窄窗、大字号、高对比度和仅键盘操作 | 三个入口和设置均可达，首页主操作和故障结论完整，卡片钻取与返回保留位置 |
