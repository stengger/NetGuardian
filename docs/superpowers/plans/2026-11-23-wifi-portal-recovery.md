# Wi-Fi 网页认证实施计划

对应 [Wi-Fi 网页认证与自动恢复设计](../specs/2026-11-23-wifi-portal-recovery-design.md)。目标是让现有守护在用户未登录时完成网页认证，或在恢复时限内切换到可用的备用网络。

## 1. 门户发现和公网证据

- [x] 增加固定地址 HTTP 门户探针并复用 Wi-Fi 出口绑定。完整诊断在接口已关联、有 IPv4 地址且公网检测失败时检查响应头。
- [x] `ConnectivityReport` 和诊断界面只记录脱敏的疑似门户线索。HTTP 探针不读取正文或跟随跳转。
- [ ] 为首次配置提供当次入口。将候选入口与已验证的认证配置核对后，再由后台认证流程消费。
- [ ] 在 `NetGuardian.Tests` 覆盖固定响应、替换 HTML、重定向、DNS 失败、超时、错误证书和目标网卡不可识别。验收时接入有线网和 Wi-Fi，验证公网探测和认证请求确实经 Wi-Fi 发出。

## 2. 无界面认证和首次配置

- [ ] 将隐藏浏览器试验中的定位和请求转发接入 Windows 后台。由 `NetGuardian.Guardian` 调度低权限浏览器工作进程，通过访问受限的本机关联通道控制该次会话。生产控制通道采用受限的管道或等效机制。当前样例使用本机调试端口，只接收虚构凭据。
- [ ] 守护侧的转发组件按已验证站点和允许的提交路径请求页面，验证目的地址和 TLS。每次使用新的会话，复用本轮 Cookie 及表单状态。验证 worker 的操作系统出站限制和目标网卡绑定，包含页面开新窗口、子帧、Service Worker 与 WebSocket 等不会被单标签页请求拦截全面覆盖的路径。
- [ ] 在 `NetGuardian.App` 的 Wi-Fi 恢复列表增加「设置自动认证」。从当前入口加载页面，确认登录站点、控件及固定选项。定位或站点不匹配时终止自动操作。试登通过同一出口验证公网后，将配置标为就绪。
- [ ] 通过受访问控制的本地接口由守护保存加密凭据，常规配置存引用。测试配置删除、更新和会话中断。检查心跳、日志、异常和残留浏览器配置，确保不包含凭据和完整会话地址。

## 3. 恢复顺序和超时预算

- [ ] 在 `MonitoringEngine` 当前网络重连前接入原地认证，并在 `ConnectAndValidateAsync` 复用同一入口。策略和候选顺序沿用 `RecoveryPlanner`。当前 Wi-Fi 接入仍有效时不提交，认证成功还需同网卡公网复测。
- [ ] 每轮每个配置最多提交一次。为首个符合条件的备用网保留扫描、连接和公网校验预算。尝试认证超时、明确拒绝或认证后的公网校验失败，立即进入备用分支。记录暂停、短期退避和自然恢复原因。
- [ ] 用引擎替身测试当前网、备用网和前后台交接。覆盖原地成功、异常和超时转备用、备用网也需认证、备用不可用、网络切换使旧结果失效及整轮取消。

## 4. 实机验收与发布

- [ ] 用 Windows 计划任务的实际守护身份和非交互会话运行原型。验收低权限进程、控制通道、网卡出口和取消后的进程清理。首次试验可使用虚构账号及回环门户。记录运行身份和会话编号。
- [ ] 在东莞理工学院校园网有门户自然弹出的时间窗口完成试登，保留认证后的公网检测结果。配合一个独立可用的备用 Wi-Fi，再验证拒绝、超时或认证成功但公网不通时的实际切网。现场按可接受短时断网的窗口安排。
- [ ] 执行全量测试和 Release 构建，通过现有安装器脚本生成安装包。提交已验证的代码与版本，推送版本标签，核对正式 Release、SHA-256 和软件内更新发现及校验。

## 2026-11-23 验证记录

在现有普通 Windows 会话中，使用隐藏 Edge 和本机回环模拟服务器复现了 JavaScript 动态渲染、运营商选项、会话地址变更和登录结果复核。单标签页请求拦截按来源、路径和方法转发给回环服务器，额外上传在客户端被阻断，服务端接收次数为零。备用探针由同一个回环服务器模拟。实际网卡绑定、操作系统级隔离和真实切网安排在实机验收。

| 检查 | 结果 |
| --- | --- |
| `node --check docs/superpowers/fixtures/wifi-portal-proof.mjs` | 通过，退出码 0。 |
| 以本机 Edge 运行模拟门户 | 10 项通过，退出码 0。覆盖首次认证、已联网、过期后新会话、登录拒绝、登录成功但公网不通、目标不匹配、控件歧义、入口未知、额外上传、登录等待超时。 |
