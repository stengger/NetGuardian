# NetGuardian 产品级界面整改计划

**目标：** 按本线程完整产品目标，使实际 Windows 主窗口的信息、操作、状态和布局可靠一致。不能以独立控件截图或测试通过代替全应用验收。

**技术与范围：** 沿用 .NET 8 / WPF / WPF-UI / xUnit；在当前分支执行，不新增 UI 框架。保留用户已有验证文档改动。网络配置、恢复策略和后台运行不得因预览验证被修改。

**设计：** 保留导航；操作和关键摘要固定，长内容可滚动；网络名称优先于辅助列；健康状态和监控归属分开；没有证据的数据标为未知，不通过地址猜测来源，不用异类请求平均值冒充网络延迟。

## 执行单元

1. **窗口可用性与状态反馈**
   - 先补真实主窗口 XAML 布局、固定摘要、静态文案、后台状态回归，观察失败。
   - 修改 MainWindow.xaml、MainWindow.xaml.cs、Views/SpeedTestView、Localizer；必要时提取小型展示状态类。
   - 策略表单滚动、保存区固定；Wi-Fi 保留可辨识名称和只读凭据标签；测速三项指标不因阅读说明消失。
   - 修正后台接管红点、不可用原因与锁失败误报；补齐中英文文案。
   - 运行全量 Core/WPF 测试、构建和对比度检查，渲染真实主窗口布局，检查后提交。
2. **数据语义与网络操作边界**
   - DNS 实际配置和待应用方案分开，默认目标不随接口名称任意选择；确认明确目标，未知来源如实说明。
   - 质量页区分 ICMP、DNS、HTTPS；替换或明确规则评分，不混合延迟。
   - 适配器统一 IPv4/IPv6、接口状态与联网能力；DHCP 明确目标和范围，部分失败准确反馈。
   - 对数据转换与外部命令边界先写测试，完整验证后提交。
3. **全应用一致性与完整生命周期**
   - 统一公共字体、间距、按钮焦点和卡片，清除重复标题；改善空、加载、失败、取消、重试与权限反馈。
   - 日志区分来源/级别，提供筛选与查找；侧栏实时流量明确统计范围及单位。
   - 首页、Wi-Fi、质量、工具各标签、DNS、适配器、策略、日志、设置均有窗口级验证，关注长文本、数据量、键盘与尺寸变化。
4. **运行与发布验收**
   - 使用真实应用运行/截图或准确记录能力限制；跨 DPI、系统主题与读屏不能以离线渲染冒充已验证。
   - 发布到独立目录，核对文件哈希与启动路径，避免旧实例造成错误验收；不强制结束用户正在使用的程序。
