# NetGuardian UI 现代化审查报告

日期：2026-11-12。审查源码基点：`07f0962`。本轮仅增加审查辅助、报告及生成物忽略规则，不修改产品代码、中文文案或本机安装。

## 结论与修复顺序

现有按钮、业务弹窗、展开箭头和无线列表虚拟化已有共用实现，不建议整体换皮或重写。主要问题来自库资源与应用资源的衔接不完整，以及多个区域缺少共同的可用视口约束。

建议顺序：**A01、A02（主题及令牌）→ A03、A04、A05、A06（共用组件）→ A07、A08（布局）→ A09、A10（细节与可访问性）**。A03 涉及严重布局问题，先建立回归案例，再随布局批次落地。每类根因独立提交，运行构建、完整测试及对应截图回归；任何已知失败必须保留并解释，不能宣布全绿。

本报告是阶段 0～1 的审查交付，不代表全部验收矩阵已在真实桌面完成。**阶段 2 强制停点：等待用户回复“继续”，此前不修复以下产品问题。**

## 阶段 1：根因清单

严重度：高＝核心内容／操作难以读取或不可达；中＝明显一致性或使用效率、可访问性缺陷；低＝细节及维护性。工作量为不含真实桌面阻塞的粗估，单位为工程日。

### A01 高对比资源没有覆盖实际模板中的全部前景／背景与边界

- 严重程度：**高**；状态：资源渲染已证实，真实系统高对比待复核。
- 根因：HCBlack 库模板预设与应用系统色混用；当前调色板覆盖 `TabView*`，但实际使用的是 WPF `TabControl/TabItem`。主／危险按钮边框又直接复用填充色，高对比填充与页面背景相同，失去可辨识边界。
- 受影响页面：诊断工具全部子页；所有主／危险按钮，包括 Wi-Fi、策略、质量、设置和业务弹窗。
- 截图：`matrix/ToolsPanel-HighContrast-1180x758-n3-100.png`（未选中标签黑底黑字）、`matrix/Dialog-Danger-HighContrast-100.png`（主按钮无边界）。
- 修复方案：先查实际 WPF-UI 4.3 模板消耗的键，统一为动态系统前景／背景配对；补主／危险按钮描边令牌，独立于填充色；验证黑、白、自定义系统色以及所有交互状态。
- 涉及文件：`Themes/Palette.HighContrast.xaml`、`Themes/Buttons.xaml`、必要时新共用标签样式、`HighContrastThemeTests.cs`。
- 工作量：0.5～1；风险：中，错误覆盖库键可能影响标题栏和内部控件；禁止用全局粗暴隐式样式修补。

### A02 应用强调色与库强调色没有共同来源

- 严重程度：**中**；状态：实际窗口与源码共同支持。
- 根因：应用主按钮固定蓝色，而导航指示、开关使用库／系统强调色；`OnApplicationThemeChanged` 接收 `systemAccent` 但只替换应用调色板，没有统一两套强调色。
- 受影响页面：全局导航、Wi-Fi 启用开关、策略和设置开关、主操作按钮；测速方向色属于有意区分，不应全部抹平。
- 截图：实际窗口前置观测到紫色导航／开关与蓝色连接按钮；可复现的隔离基准为 `matrix/WifiPanel-Dark-1180x758-n36-100.png`。静态矩阵默认强调色不能单独复现系统紫色。
- 修复方案：统一应用交互强调令牌并映射库控件；保留健康／警告／错误及上下行方向语义。高对比继续服从系统色。
- 涉及文件：`App.xaml.cs` 的主题展示入口、`Themes/Palette.*.xaml`、主题一致性测试。
- 工作量：0.5；风险：中，需覆盖主题运行中切换与库资源优先级。
- 需确认取舍：推荐统一为现有应用蓝色；另一方案为全应用跟随系统强调色，会改变主按钮既有观感。

### A03 共用提示区域没有维护正文的最低可用视口

- 严重程度：**高**；状态：稳定终态截图已复现。
- 根因：根 Grid 给提示区 Auto 行，提示高度上限仅按窗口 40% 计算，未扣除页面标题、操作、上下文及两个列表标题。提示展开后页面被挤压；现有测试只检查不覆盖操作栏，没有约束正文可用性。
- 受影响页面：全部页面；Wi-Fi 分区和有大量表格的工具页最明显。
- 截图：`matrix/Feedback-Dark-Danger-True.png`（1180×758，恢复优先级入口消失、首条网络被裁）、对照 `matrix/WifiPanel-Dark-1180x758-n36-100.png`。
- 修复方案：用共用内容视口预算约束提示区，正文最低可用空间先满足；提示正文／详情在提示容器内部滚动，保留关闭和所有操作。
- 涉及文件：`MainWindow.xaml` 根布局、`Themes/Tokens.Common.xaml`、`Presentation/FeedbackPresenter.cs`、反馈布局测试。
- 工作量：0.5～1；风险：中，长提示、三条队列、屏幕阅读和键盘滚动可能互相影响。
- 需确认取舍：推荐保留底部专用提示区，按正文最低视口动态限制其高度；备选浮层可减少挤压，但会遮挡内容。**不推荐浮层**。

### A04 共用样式在主窗口与页面局部重复，令牌迁移未覆盖展示代码

- 严重程度：**中**；状态：源码已证实。
- 根因：卡片／标题／表格公共样式仍在 MainWindow 内；测速又定义 Card、32/24/16 字号与 7/10/18/20 等间距；`ResponsiveLayout`、托盘菜单代码直接设尺寸。仅调整现有令牌不会同步这些位置。
- 受影响页面：全应用卡片、表格、测速页、无线上下文、DNS 编辑区、托盘菜单。
- 截图：`matrix/ToolsTab1-Light-1180x758.png`、`baseline/policy-1040.png`、`baseline/tray-menu-Dark-zh-CN.png`；根因以源码为准，截图展示字号和留白差异。
- 修复方案：先补齐角色令牌，再抽取现有共用卡片／标题／表格字典，测速和菜单显式复用；展示代码使用动态资源引用，避免换主题或令牌时被本地值覆盖。几何坐标、零值及布局权重需区分，不机械把每个数字都做成无语义令牌。
- 涉及文件：`Themes/Tokens.Common.xaml`、新共用样式字典、`App.xaml`、`MainWindow.xaml`、`Views/SpeedTestView.xaml(.cs)`、`Views/TrayContextMenu.xaml(.cs)`、`Presentation/ResponsiveLayout.cs`。
- 工作量：1～1.5；风险：中，资源解析顺序、共享模板及测速响应式覆盖；分小批迁移、同尺寸回归，不做无关重构。

### A05 按钮状态的视觉差异过弱，危险操作长期争抢主层级

- 严重程度：**中**；状态：模板与截图共同支持。
- 根因：共用按钮 hover/pressed 主要依靠 0.98/0.96 不透明度，两个状态又用同一边框；DangerButton 长期整块亮粉，紧邻蓝色主操作。危险确认前的普通删除入口与最终破坏性确认未区分角色。
- 受影响页面：所有普通／主按钮；Wi-Fi 删除、危险确认弹窗。
- 截图：`matrix/WifiPanel-Dark-1040x660-n36-100.png`、`matrix/Dialog-Danger-Dark-100.png`；hover/pressed 来源为 `Themes/Buttons.xaml`，真实按下对照图尚缺。
- 修复方案：新增明确且克制的悬停／按下填充和描边令牌，保持尺寸不变；普通危险入口用中性底＋语义色文字／边框，最终危险确认保留明确危险层级。禁用和高对比独立检查。
- 涉及文件：`Themes/Buttons.xaml`、`Palette.*.xaml`、按钮状态／焦点测试。
- 工作量：0.5；风险：低～中，需确认错误色不会与主强调混同；不更改删除业务或按钮文案。

### A06 共用展开模板没有覆盖所有业务展开入口

- 严重程度：**中**；状态：源码已证实。
- 根因：日志、测速、Wi-Fi 和提示详情显式采用 `ContentExpanderStyle`，设置中的 `UpdateNotesExpander` 未引用，更新说明沿用另一套默认模板，箭头、焦点、间距和动效不保证一致。
- 受影响页面：设置更新说明，与日志／测速／Wi-Fi／提示的展开入口对比。
- 截图：`baseline/updates-Light-zh-CN.png`、`baseline/logs-expanded-1040-660-zh-CN.png`；更新说明的三主题交互截图需在修复批次补齐。
- 修复方案：更新说明复用现有展开样式；扫描剩余业务 Expander 显式引用同一模板，不覆盖第三方控件内部 ToggleButton。
- 涉及文件：`MainWindow.xaml`、`Themes/Expansion.xaml`（仅确有缺项时）、`UpdateLayoutTests.cs`、`ExpansionInteractionTests.cs`。
- 工作量：0.25；风险：低，保留内容滚动与更新状态可见性；箭头中心及减少动画已有实现，避免重复改造。

### A07 Wi-Fi 上下文和说明使用过多永久纵向区域，列表只有最低一行契约

- 严重程度：**中**；状态：位图与实际窗口均支持。
- 根因：当前连接卡、选中说明卡、双击说明、扫描状态分别占 Auto 行；紧凑策略只在窗口高度小于 600 生效，正常最小 660 下仍完整展示。上下列表已独立虚拟化，但最低视口只保证约一条记录；上区还受 40% 上限影响，默认窗口有空间时仍只能看少量周围网络。
- 受影响页面：Wi-Fi 管理，空数据、长 SSID、36+ 网络、详情展开均受影响。
- 截图：`matrix/WifiPanel-Dark-1040x660-n36-100.png`、`matrix/WifiPanel-Light-1180x758-n36-100.png`、`baseline/wifi-folded-1040-32.png`。
- 修复方案：基于内容实际可用高度选择紧凑展示；合并视觉容器而保留现有文字、展开入口和功能；用可用视口及最小行数决定分区分配，保留独立滚动和虚拟化，不加大固定高度。
