# 无人值守网络恢复实施计划

目标：校园网上游故障时自动尝试另一独立 Wi-Fi；网卡异常、进程故障、重启后未登录时仍有本地恢复入口。

设计：复用 Core 的检测与恢复引擎，增加无界面 Guardian 进程。计划任务开机以 SYSTEM 运行 Guardian，直接监督进程；后台固定使用 ProgramData 配置，界面在安装后台后读取同一份配置。机器级独占防止多个恢复控制者。正常上游断网优先切网，设备故障才启用管理员恢复。整机重启保持独立显式开关且默认关闭。

约束：中文输出与新增注释；不丢弃既有未提交重构；不实际断网/重启/安装任务；不删用户配置和已发布可用版本；只删除已证明重复或可重新生成的内容。

## 任务与验证

- [x] 1. 恢复状态机：MonitoringEngine、RecoveryPlanner 与 MonitoringTests。先补上游失效仍关联、候选无互联网、无轻恢复可用、停止取消、动态周期的失败用例，再修复。连接成功必须通过完整探测；失败网络短期退避；检查与恢复有总截止时间。
- [x] 2. 网络判断与配置：ConnectivityTester、MonitorPolicy、SettingsStore 及测试。用可注入的外部探针验证网关 ICMP 失败仍继续公网验证、单个 HTTPS 目标、配置 null 字段回退。统一配置路径并原子持久化。
- [x] 3. 系统恢复边界：ProcessCommandRunner、HighRiskRecoveryService 及测试。命令超时与终止；取消后仍保证启动/启用收尾；PnP 只读状态与设备级恢复；保存跨进程冷却/重启上限，禁止普通上游故障重启电脑。
- [x] 4. 无界面后台与界面协作：新增 Guardian 项目、共享路径与独占租约、后台健康状态。配置热加载、异常退出供任务重试；心跳监督可发现假死；界面不与后台抢控制权。
- [x] 5. 启动部署：修正发布版不需要 SDK、开机 SYSTEM 任务、失败重试与周期监督、单独卸载后台。发布脚本输出 App 与 Guardian；仅生成可审查脚本，不在本机注册。
- [x] 6. 目录收敛：更新 README 为唯一当前使用说明，历史设计/审查文档归档；移除确认无效的重复实现与生成缓存，保留实际运行资源。检查引用和 Git 忽略规则。
- [x] 7. 全量测试、Debug/Release 构建、脚本语法/模拟部署检查、独立代码审查与修复。每个逻辑单元验证通过后中文提交；只暂存相关文件，最终报告保留的既有未提交改动。

## 验收关注

- A 有 SSID 但无公网，B 有公网：必须验证 B 后才报恢复。
- A/B 均无公网：有限重试、持续探测、不得无止境重启设备/电脑。
- 命令挂起/用户停止：检查可退出，已关闭设备必须尽力重新开启。
- 进程退出/假死/系统重启无人登录：开机任务与监督可重启守护。
- 配置变动/损坏/缺字段：保留最近有效配置或回退备份；配置热加载不静默停守护。

说明：真实断网、设备重启和重启未登录验收需另选有本地回退的维护窗口；本轮使用外部依赖替身和无破坏模拟验证。
